# Raids, Part 2: the raid game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every WW raid family playable alone, following the story date and the Monday rotation, for every boss whose graphics are complete; past raids reachable from a Raid Catalog; the other bosses join by data alone as their textures are recovered.

**Architecture:** A generator (`server/make-raid.js`) turns the private census and values into master rows and `server/game_data/raids.json`, keeping only raids whose models pass a completeness check. Pure modules hold the rules (`raid-calendar.js`, `raid-fight.js`, `raid-rewards.js`) and `server/routes-raid.js` connects them to the protocol and the save. One raid runs end to end first (Tasks 1-7), then the data widens family by family with no change to the fight code.

**Tech Stack:** Node server with plain `node server/test-*.js` tests, Python importers (`recon/tools/`), LDPlayer bench instance 0.

**Spec:** `docs/superpowers/specs/2026-11-01-raids-design.md`. **Client facts:** `docs/notes/raid.md`.

## Global Constraints

- Only the original client runs: no client patch. Fake players or simulated helpers are forbidden.
- Every reconstructed value is labelled in the data (`reconstructed: true` with the reason) and declared in the Notices. A later source replaces a value with no design change.
- HP is never lowered. If a `maxpower` deck cannot finish a tier on the bench, lengthen the timer first.
- JP-only raids (185 rows) stay out of this plan: Answer 3 of the spec puts them later, Catalog only, labelled JP.
- Calendar of record: `raid_census.json`. Apply `raid_rewards\CORRECTIONS.md` on top of `raid_values.json` and the census when building; never edit the source files.
- Private sources are read through `KHUX_RAID_SRC` (default `D:\Progetto_Restauro_KH_UX\private\events\sources`) and never copied into the repository. Output goes only to the git-ignored `server/master_data/` and `server/game_data/`. Our own choices go in the versioned `server/raid_config.json`.
- No SE files, decompiled code, addresses or private sources in the public repository; client internals stay in `tmp\raid_spike\client\FLOW.md`.
- Ids: raid stages 980000-989999, raid `evStage` 8000-8999, raid `raidSetting` 30000-39999, raid `raidEnemy` bodies 2000000 + 10n with parts at +1..+5 (`weakness` - 1), raid boards `sphereBoardId` 3000000+. `raidReward` id = `raidEnemyId * 100 + table * 10 + band`, tables 1 Victory, 2 MVP/Host, 3 All Points. The generator stops if any id collides with an existing row.
- Bench: one script at a time, taps only with the game alive, SKIP on any dialogue, battle checks are the user's. Master revision only goes up (now 229), in the 4 session scripts and `tools/play/packaging/make-play-package.ps1`. After `update-resources.ps1` tap KHUX START (200,1020) + Download (1220,715). Never `-Quick` when a newer version exists than the one installed. Use a copy of `maxpower` (`raid2`), never `maxpower` itself.
- Commit + push each verified step, English messages, `git -c safe.directory=*`, `git commit -F <file>`, `git pull --rebase` before the push, UTF-8 (keep an existing BOM on `.ps1`). Windows DNS on 192.168.1.185 during the session, automatic at the end.

## Decisions the spec left to this plan (builder's call)

1. **A calendar raid whose boss is not available.** Its tier is simply not offered: no substitute boss, since a stand-in would be invented content. If a week has no available tier it behaves like a week without a raid (Answer 4: empty list, story bosses and Catalog remain). The Catalog lists it as «Not restored yet» and the Notices explain why. Availability is computed from the files, so a recovered boss appears at the next build. Measured with today's 29 bosses, on the 128 weeks of `week_tier_hp`: 86 complete, 7 partial, 35 with no raid; 243 of 340 tier rows; 50 of 83 other WW event rows; 94 of 126 story ranges. Bosses `5000` and `9101` stay out until their `put_down` gaps close.
2. **Catalog.** One kept raid at a time, as in Special, because only one boss can be alive; raids later than the story date stay visible and locked.
3. **Spawn counter.** One rule for everything: `getPoint.raidPoint` of `/stage/clear` adds up to the original threshold `misc` 110 = 8600 (Eggcognito row 3000, so 3 eggs; normal enemies give about 57-192, which is the «about 80 kills» of the JP wiki). In bonus time the threshold is 6000 (2 eggs). Inferred from those numbers, declared.
4. **Bonus hours.** 2:00, 8:00, 14:00, 20:00 PT, one hour each, computed on the real clock. Quest AP 0 in bonus, 5 on weekends, 90 on weekdays from 2019-07-15; earlier periods from the week's own `ap` field.
5. **Returning weak points** come back at 50% of their row's HP: the sources say «partial» with no figure, so this is reconstructed. The 3 minutes count from the end of the latest fight, which is how «the timer resets at every fight» is applied.
6. **Raid Coins** are one balance, `raidSpherePoint`, kept across weeks: the field is unique in the client, and the only report (r/KHUx as37e6) says coins stayed.
7. **Story bosses** do not count Proud, Special or event quests. A boss alive blocks new spawns of any kind.

## Review Focus

1. A pending reward with a slot outside 1..`validReward`, or for a row no longer served: `/raid/reward` runs at every opening of the quest screen, so it would lock the player out of Quests. Expected: bad entries are dropped and logged. Pinned in Task 4.
2. A boss from an old session, after a restart or a jump of the fake clock: `timeLeft` in the past must give `raidStatus` 2 once, then 0, and a game killed mid-fight must leave the boss alive and the AP spent. Pinned in Task 3.
3. A week change while a boss is alive: it keeps its row, timer and damage until it dies or flees, even if it is no longer in the list of the week. Pinned in Task 3.
4. A master revision that names a model missing from the installed resources: a native crash. Expected: the generator refuses to emit it and the session scripts refuse a revision newer than its resources. Pinned in Task 1 and Task 2.
5. A save over the 3000-medal storage (seen 25-10: every quest refused), or a medal reward with a full box: the raid must still end and the reward must reach the Present Box. A save with no `player.raid` must load. Pinned in Task 4.
